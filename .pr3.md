What it adds, and why it is shaped this way

* One passage at a time in a window of 1,024 tokens, which is the figure the budget's anonymous
  memory was worked out for (the key and value cache is a fixed 112 KiB a token). A list handed to
  the library would be a batch whose cache is held at once.
* The part states the file's OWN identity: the install's model name, the first twelve characters of
  the file's SHA-256 as the revision, the width the library reports. The application records that
  beside every vector and refuses a vector under any other revision, so a file replaced by hand is a
  new revision, which is the model change that has no symptom made into one. The digest is the one
  the fetch recorded, trusted only while the file keeps the length it recorded, and hashed (once, at
  load) otherwise; the readiness route reads the record and never hashes, so the health check stays
  free.
* The install must declare that revision (`INSTALL_EMBEDDING_REVISION`) and nothing tells it what to
  write, so the model server screen now shows the one the server holds beside the one the install
  declares, in words, and an install check holds the two equal with a sentence for each way they
  part (a different revision; none stated, so the file is not fetched).
* The worker keeps what the server measured of itself. Both clients take an `observer`, a
  thread-safe `PeakKeeper` takes the reports from the thread a client is called in, and the job
  flushes it in a `finally`, each report in a savepoint of its own: a batch that ran the server out
  of memory is the one whose peak is wanted, and a table that will not take a row costs that row and
  not fifty embedded passages. Bounded at one ring for every part.
* Unit length: a vector that is not is made so, because the column's search is by angle.
* The model server screen and the check read the server over the readiness route, which now also
  states each chosen part's weights' revision.
* `make_client` gained the `observer` parameter, so `test_inference_client.py`'s signature test
  lists it beside `env` and `timeout_seconds`. It carries no address, so the property that test
  holds (nothing but the install says where text goes) is unchanged, and the test says so.

What was rejected

* Hashing the file on the health check: a gigabyte every twenty seconds.
* Echoing the requested model in the answer: the part states its own and the application refuses a
  disagreement; echoing would record vectors under weights that did not make them.
* Embedding a question with the model's instruction prefix: the wire has no field that says a text
  is a question, so every text is embedded as a passage, which is a loss of retrieval quality nothing
  here has measured. Adding the field is a change to the wire's contract.
* M7.7.8's "previous vectors keep serving while the corpus is rebuilt" is not built: the product
  decided against it on purpose and put it to the owner as needs-rupash 186, which is still open.
  The leaf is not blocked on memory any more; it waits on his answer.
