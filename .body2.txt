The model server reads documents: layout, scanned pages and a general reader, sent to by the queued ingest job and waited for when they are not there

Stacked on the frame (the model server as one optional service that holds one part at a time). This
adds the three parts that read a document, and the product's route to them. Everything is behind the
service being switched on (`INSTALL_SERVICES`), the `model_server` feature and a part being chosen
(`INSTALL_MODEL_PARTS`); an install that did none of those reads exactly as it did.
Leaves touched and none closed: M7.2.1, M7.2.3, M7.2.4, M7.7.10, M7.7.11.

**Never run against the real libraries.** Nothing in this repository has installed Docling,
Tesseract, pypdfium2, Pillow or Apache Tika, so the calls into them are written from their
published interfaces and have not been executed. Each part module says so at its head, and what
the tests show is this program's own work: the request it reads, the blocks it lays out, the
refusals it may say, the processes it leaves behind. The nearest the repository gets to the server
without Docker is `test_model_server_end_to_end.py`: the product's real clients over a real loopback
socket to the real gateway and supervisor, with the library and the process boundary stood in.

What it adds, and why it is shaped this way

* Three parts as child processes of the supervisor, each in a process group of its own, so ending a
  part ends what it started (the general reader's JVM among them). Without the group the idle stop
  would give back the worker's memory and leave the JVM's, which is the memory the design sells.
* One request shape for the three, a document as base64 in JSON with its digest and type and no
  filename, decoded once to a file in a directory the part owns and deleted before the answer is
  sent. A refusal is the application's closed four causes and nothing a library said, because a
  library's message quotes the file. An exception that is this program's own mistake (a TypeError, an
  AttributeError) propagates as an outage and is never read as a fact about the document.
* The scanned-page part answers with a confidence for EVERY page, and the application applies the
  floor to each: `read_by_page` keeps the sure pages, lays the kept blocks out again so every offset
  is true of what was kept, and names the pages it left out (M7.7.10). One figure for a document
  passes a scan whose tenth page is noise. A page with no recognised word is not named, because a
  blank back side is the commonest page of a scan.
* The route is the paths' own order (layout, the reader in this process, scanned pages last), the
  in-process reader is the fallback and the general reader is the fallback only for what the
  in-process reader cannot open (a presentation). A type no chosen reader opens has an empty route
  and the door refuses it in the door's words. With no document part chosen the route is empty and
  nothing is recorded, as before.
* An outage is not a verdict on the file. A part that is loading, busy or down is `PARSER_UNAVAILABLE`,
  the route does not fall back on it, and the ingest job raises (`ReaderNotAvailableError`) so the
  recovery sweep re-drives it (the task is `Redrive.SAFE`) and the ticket stays queued. The cost is
  stated: the sweep re-drives three times, so a server down for longer leaves the job in the dead
  letters with the ticket still saying queued.
* The ingest job reads off the event loop (`asyncio.to_thread`). A reader that takes minutes would
  otherwise block the loop, stop the worker's heartbeat, and have the sweep re-drive a job that is
  still running.
* A photograph (PNG, JPEG) can now reach the scanned-page part: the structural check judges its
  header (a header claiming more pixels than any page has is refused as expanding without bound, one
  that cannot be read is unopenable), because before that reader existed an image was refused
  outright and so could never be sent to it. The door accepts one only where the part is chosen, and
  only at the queued door: the console's own single-file upload still reads in the application's
  process and does not wait for a part to load.
* M7.7.11: the worker's start-up finding that the door admits more than the server is sized for is
  now derived from the install's own choice of parts and upload size, said only where the server
  reads documents, and said for an install that runs the server even where it declared no embedding
  revision. An install check holds the recorded memory peaks against the limit the settings cost.
* The installs' existing tests that moved: the layout request-ceiling test, the closed-fields test
  of `OcrReading`, the structural check's refusal of an image, and the advisory tests.

What was rejected

* Falling back to the weaker reader when the stronger is unavailable: an hour of downtime would put
  every document ingested in it on the fallback with nothing to re-read them.
* Calling a Tika 422 `encrypted`: it does not say, and the word would send somebody to remove a
  password that may not be there. It is `unsupported`.
* A check that sends the largest upload (25 MB) through every part on every update: it costs
  minutes. The largest upload is held against the limit by the peaks the server has really recorded,
  which is only as good as the documents it has really read (M7.7.11 stays partly built).

Not done: the parts run for real (the image is unbuilt and unpublished, the weights are not
fetched, nothing is pinned: needs-rupash 235); the pages left out are named in the ticket and the
item's notice but no screen shows the item's notice yet; a check that sends the general reader a
format the layout reader cannot open.

Reused: knowledge.parse_layout (the contract and its decoder, unchanged but for an optional model
name), parse_ocr (the contract; gains the per-page floor), parse_paths (`parse_by_route`,
`RoutedParser`, the order rule), scanning (`parse_scanned`; gains `ReadWithGaps`), text_path (the
reader in this process and `laid_out`), ops.inference_client (its transport and breaker name),
ops.model_server (the parts, paths and sizing), ops.acceptance_checks_knowledge_models (the start-up
advisory check). Replaced: the advisory's fixed ceiling (now the install's own), and the closed-fields
and ceiling tests above, each argued in its docstring.
