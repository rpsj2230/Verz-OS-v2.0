## Ask: dictation through the person's own browser (M40.7.3, owner decision 220 B)

A Dictate your question button on Ask uses the speech recognition built into the browser. No server route, no vendor, no key, and nothing is requested from our side; tests assert that on every request the page makes and on fetch, XMLHttpRequest, WebSocket and sendBeacon.

- `console/src/pages/askDictationCore.ts`: finds the recogniser (standard or prefixed name), listens in `navigator.language` (never a constant), asks for finished phrases only, `appendSpoken` adds them after what was typed, cut at the question limit.
- `console/src/pages/AskDictation.tsx`: type=button toggle with `aria-pressed`, a status live region present from the start, a plain sentence in a browser with no recogniser, a sentence for a blocked microphone that says how to allow it, one for each other failure; aborts when the question is sent and when the page is left.
- `Ask.tsx` places it straight after the question field. `skip-to-answer.test.tsx` pins the tab order, so it gains the case with a recogniser and the 44px target for the new button; existing cases are unchanged (no recogniser, no extra stop).

The pure module is `askDictationCore.ts`, not `askDictation.ts`, because the component is `AskDictation.tsx` and macOS file systems are case-insensitive: the two names are one file there.
